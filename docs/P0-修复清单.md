## FIX-01　T-02　「每周 N 天」被当成「天/月」

- **问题**：描述「每周工作 4 天」时，原代码把 `days=4` 直接按「天/月」喂给计算引擎，月收入、保本量、回收期全部错误。（报告 T-02）
- **改前**（`server.cjs` `sanitize`）：`unit: String(it.unit || '')` 原样采信模型单位，非 skill 场景不做任何换算；前端 `x.days` 直接当日/月用。
- **改后**（`kz-schema.js` `canonicalize`）：
  - 单位含「/周」或来源为「每周 N 天」且未换算过 → 用 `每周天数 × 每月周数` 换算成天/月；
  - **换算因子缺失（没有「每月几周」）→ `blocked`，值置空，进 `missing`，生成追问，禁止进入计算**。
- **位置**：`kz-schema.js` `canonicalize`（days 段）；`server.cjs` `sanitize` / `extractFields` 调用点；`index.html` extract 循环 blocked 分支 + `mustAskUser`。
- **验证**：`scripts/verify-p0.mjs` 【4】【5】——缺周数时 `blocked=['days']`、`value=null`；补「每月4周」→ `days=16`、`sourceType=converted`。
- **核对结果**：☐ 通过

## FIX-02　T-01　wage 被误填成售价

- **问题**：家教「每小时收费 80 元」时，接口同时返回 `price=80` 和 `wage=80`，机会成本被错误放大。（报告 T-01）
- **改前**：`sanitize` 对 `wage` 与其它字段一视同仁，模型填了就进。
- **改后**（`kz-schema.js`）：`WAGE_EVIDENCE = /参考时薪|兼职时薪|机会成本|参考工资|人工成本|…/`；
  无证据 → 删除 `wage` 并生成追问；有证据才保留。
- **位置**：`kz-schema.js` `wageHasEvidence` + `canonicalize`（wage 段）。
- **验证**：`scripts/verify-p0.mjs` 【6】——无「时薪」证据丢弃，有「兼职时薪」保留；`test/schema.test.cjs` 两条用例。
- **核对结果**：☐ 通过

## FIX-03　T-04　来源短句无核验

  前端 `srcLabel()` 按 `KZSchema.SOURCE_LABELS` 显示（AI 识别 / 规则识别 / 单位换算 / AI 推断 / 用户填写 / 默认假设）。
- **位置**：`kz-schema.js` `canonicalize`；`index.html` `srcLabel()`。
- **验证**：`test/schema.test.cjs`「来源短句能在原文找到 → ai；找不到 → inferred」。
- **核对结果**：☐ 通过

## FIX-10　T-06 / P0-5　试卖对照（预测 vs 实际）

- **问题**：试卖记录只显示平均销量，不能证明模型被校准。（报告 T-06）
- **改后**：新增 `kz-trial.js`（纯函数）：按统一口径算 **实际单位成本 / 实际单位边际 / 实际边际时薪 / 销量偏差**，并生成「下一轮调整建议」；
  页面试卖区新增「📊 预测 vs 实际对照」面板与「导出验证报告（JSON）」按钮。
- **口径**：实测「成本」= 直接变动成本（原料+包装）；实际单位成本 = Σ实测成本 ÷ Σ实测销量；实际边际时薪 =（Σ收入 − Σ成本）÷ Σ工时。
- **位置**：`kz-trial.js`；`index.html`（`renderTrialCompare`、`export-verification`、试卖区 DOM）；`server.cjs`（托管 `/kz-trial.js`）。
- **校准（真实数据）**：用《计划书》第五章表 8 乌梅小番茄总账（12 次、194 盒、食材 480 元、工时 36h）：
  - 成本估算准确（2.47 元/盒）→ 实际 2.47 vs 基准 2.47（+0.2%），边际时薪 22.26 vs 22.03（+1.0%）→ 「口径基本可信」
  - 新手自估（5 元/盒）→ 实际 2.47 vs 基准 5.00（−50.5%）→ 「实际单位成本低于假设」
- **验证**：`test/trial.test.cjs`（7 条）；`scripts/verify-p0.sh` 全过。
- **核对结果**：☐ 通过

## FIX-11　T-03　洗鞋等按单服务的合并成本被漏计

- **问题（线上冒烟测试发现）**：洗鞋描述「清洁剂和包装成本 5 元」时，AI 把洗鞋归到「其他经营场景」，因而不是服务类→ 合并成本**没落进 raw，被静默丢掉**（成本少算、结论偏高）。（报告 T-03）
- **改后**（`server.cjs` `normalizeServiceCosts`）：按单/按双的服务（匹配 `每双|按双|清洁剂|洗鞋|代洗`）即使被归为 `other`，也把「清洁剂和包装」类合并成本计进 `raw`；服务类的去重逻辑仅对 `kind==='service'` 生效。
- **位置**：`server.cjs` `normalizeServiceCosts`。
- **验证**：线上真实 AI 提取洗鞋描述 → `raw=5`（元/双），`blocked=[]`；5 预设冒烟全部正常。
- **核对结果**：☐ 通过
