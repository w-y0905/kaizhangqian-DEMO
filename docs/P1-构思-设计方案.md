## 〇、总原则（防止拆东墙补西墙）

1. **分层不变**：输入 → AI 理解 → 标准化(schema) → 计算(calc) → 展示。新功能一律不得绕过 `schema` 把原始值直接喂给 `calc`。
2. **能算的逻辑都进纯函数模块**（`kz-*.js`）：限流计数、对比算法、知识库匹配、报告生成 → 有测试、不污染页面。
3. **契约版本化**：`schemaVersion` 只在「字段/单位口径」变时 +1；`formulaVersion` 只在「计算口径」变时 +1。P1 的知识库/方案对比**不应**改动这两个版本；新增独立 `kbVersion`。
4. **演示路径隔离**：任何新功能默认不影响 5 预设 + 乌梅标杆路径；用 feature flag 或「仅自定义场景触发」。
5. **每个改动配测试**：改完先跑 `npm test` + `bash scripts/verify-p0.sh`，再部署；部署后跑线上冒烟（5 预设 + 乌梅 + 遛狗 blocked）。
6. **小步提交 + tag**：每项完成打 tag，随时可回滚到 P0。

## 一、T-10 限流与额度告警（建议第一个做）

- **目标**：防刷、控 DeepSeek 成本、演示时段不被挤爆。
- **现状**：无任何限流；有 20KB body 上限；有 6h 内存缓存 + 启动预热。
- **设计**
  - 新增 `kz-limit.js`（纯函数）：滑动窗口计数，输入 `(bucket, key, now)` 返回 `{allowed, remaining, retryAfter}`。
  - 服务端接：**先查缓存 → 命中直接返回且不计限流**；未命中才计。
  - 维度：按 IP（如 20 次 / 10 分钟）+ 全局（如 500 次 / 天，可配环境变量）。
  - 超限：返回 `429` + `Retry-After`；前端友好提示「请求较频繁，请稍候」。
  - 告警：全局计数超阈值 → 写日志；每日汇总（可复用现有微信通知，或先只写日志）。
  - 白名单：演示 IP / token 跳过限流（保演示）。
- **影响面 / 风险**：① 反代下拿不到真实 IP（需读 `X-Forwarded-For`，须确认 nginx 是否透传）；② 阈值过严误伤正常用户；③ 重启丢计数（内存态，可接受）。
- **依赖**：确认 nginx 是否透传客户端 IP。
- **验收**：脚本连打触发 429；缓存命中不限流；5 预设 + 乌梅不受影响。
- **工作量**：小。

## 二、T-09 收尾：架构图 + fixtures（低风险，可并行）

- **架构图**：画「输入 → AI 理解 → 标准化 → 用户确认 → 计算 → 验证输出」六层（配省赛证据用）。
- **固定 fixtures**：把 `scripts/verify-p0.mjs` 里的 mock 输出抽到 `test/fixtures/*.json`，供测试与评审复用。
- **影响面**：纯新增文档/数据，零代码风险。
- **工作量**：小。

## 三、T-07 演示保护（现场不翻车）

- **目标**：断网 / 模型抖动 / 冷启动都能稳定演示。
- **现状**：6h 内存缓存 + 启动预热；超时 25s/32s；规则回退；模式标识。
- **设计**
  - **缓存持久化**：预热结果落盘（`*.json`），重启即用（现在重启要重新预热）。落盘带 `schemaVersion`，版本不符自动失效。
  - **演示模式开关**：`?demo=1` → 只走缓存/规则、不实调 AI、隐藏耗时、显式标注「演示模式」。
  - **超时兜底**：AI 失败 → 规则回退 → 明确「规则模式」（已有）；可选「3s 未响应先显示预置占位」，但**必须标注为预置**，防止被误当实时结果。
  - **离线录屏**：属材料（非代码），可另出操作清单/脚本。
- **影响面 / 风险**：缓存落盘要防脏数据（版本校验）；`demo` 参数绝不能渗进正常路径。
- **工作量**：中。

## 四、场景成本知识库（差异化重点）

- **目标**：AI 追问更专业、更贴合校园场景；规则回退也能生成专业追问。
- **现状**：`server.cjs` 里 `SCENE_DEFS` + `sceneQuestions` + `RELEVANT_HINTS` 写死。
- **设计**
  - 新增 `kz-scene-kb.js`（纯数据 + 查询）：每场景 → 常见成本项、典型区间、易漏项、追问清单、计价单位、常见定价。
  - 三处复用：① 注入 `buildPrompt` 给模型上下文；② 规则回退生成追问；③ 前端做「合理区间」提示（如杯成本通常 1–3 元）。
  - 独立 `kbVersion`，与 schema/formula 解耦。
- **影响面 / 风险**：改 `buildPrompt` 影响**所有** AI 提取 → 必须跑全预设回归；防止模型「套模板」→ 措辞加「仅供参考」，并坚持「只填原文明确数字」。
- **工作量**：中。

## 五、方案对比（纯新增展示）

- **目标**：多个创业构想同盘比较。
- **现状**：本地保存方案（≤10 条），无对比视图。
- **设计**：复用已有 `buildSnapshot()` 结构化快照 → 新增 `kz-compare.js`（输入 2–4 个快照 → 输出对比矩阵 + 排序）→ 前端新增对比视图。**`calc` 不动。**
- **影响面 / 风险**：低（纯新增）；注意 localStorage 容量（沿用 10 条上限）。
- **工作量**：中。

## 六、验证报告增强 / 用户试用记录

- **目标**：证据链更完整。
- **现状**：`kz-trial` 已有偏差对照 + JSON 报告。
- **设计**：多轮对照（假设修正前/后）；可读版（导出 PDF/表格）；选择性记录同学试用数据。
- **影响面 / 风险**：低。
- **工作量**：中。
